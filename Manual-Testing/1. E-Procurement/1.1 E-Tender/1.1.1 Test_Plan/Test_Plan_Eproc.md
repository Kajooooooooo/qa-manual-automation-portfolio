# Test Plan - E-Tender

## 1. Test Objective

To verify that the E-Tender procurement process functions correctly from package creation through vendor participation, bid evaluation, negotiation, and winner determination.

## 2. Scope

### In Scope

- Package Creation
- Package Publication
- Vendor Registration
- Registration Evaluation
- Clarification Session
- Bid Document Upload
- Bid Document Opening
- Bid Document Evaluation
- Negotiation
- Winner Determination

### Out of Scope

- Performance Testing
- Security Penetration Testing
- Infrastructure Testing
- Third-party system testing

## 3. Test Type

- Functional Testing
- Positive Testing
- Negative Testing
- UI Testing
- Regression Testing
- User Acceptance Testing (UAT)

## 4. Test Environment

| Item | Details | :
| Application | E-Procurement |
| Module | E-Tender |
| Environment | Test / Development |
| Browser | Google Chrome |
| Operating System | Windows |
| Testing Approach | Manual Testing |

## 5. Test Flow
The E-Tender process covered by this test plan is:
1. Create Work Package
2. Publish Work Package
3. Vendor Registration
4. Registration Evaluation
5. Clarification Session
6. Vendor Bid Document Upload
7. Bid Document Opening
8. Bid Document Evaluation
9. Negotiation
10. Winner Determination

## 6. Entry Criteria
- Test environment is available.
- E-Tender module is accessible.
- Required test accounts are available.
- Test package data has been prepared.
- Required vendor test data is available.
- Application build is ready for testing.

## 7. Exit Criteria
- All planned test cases have been executed.
- Critical defects have been resolved or accepted.
- Regression testing has been completed.
- Test execution results have been documented.

## 8. Test Deliverables
- Test Plan
- Test Scenarios
- Test Cases
- Bug Reports
- UAT Documentation

## 9. Risks
| Risk | Mitigation | :
| Test environment unavailable | Coordinate with the responsible team |
| Test vendor data unavailable | Prepare vendor test data before execution |
| Workflow is blocked by a defect | Report the defect and continue independent test scenarios |
| Application changes during testing | Record the tested application version/build |

## 10. Test Schedule
Testing will be performed based on the availability of the E-Tender application build, test environment, and required test data.
